Apartment Ledger Pro

Architecture overview · Docker · Postgres · Fastify · TanStack Start

1. Personas & surfaces

Resident Dashboards

Read-only analytics: Overview, Head Drill-down, Cashflow, Income, Balance. Content is filtered by dashboard_settings.

Admin Dashboards

Same analytics at community scope + Action Needed queue, Cost Alerts, Vendor Insights, Collections, Income Optimisation.

Admin Controls

Transactions CRUD, Residents & whitelist, Dashboard toggles, Audit trail, CSV imports. Separated from dashboards in nav.

4. Auth

OTP over email, whitelisted addresses only. No clickable magic link. Requesting an OTP for an unknown or revoked email returns 200 { ok: true } silently (no enumeration). See AUTH.md for the full sequence.

5. Vendor handling

Vendors are surfaced only through insight dashboards (/admin/vendors, expense drill-downs). There is no admin vendor CRUD screen and no /api/admin/vendors endpoint. Vendor rows are populated by CSV imports or created on the fly during transaction ingest; cleanup happens through import_rules during the map step.

6. Sparse-data strategy

Line items are non-uniform month to month. Every time-series read left-joins a generated month spine so absent months still render as 0. See DATA-MODEL.md → Sparse data.
